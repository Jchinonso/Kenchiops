# Postmortem: CI Pipeline Outage - January 15, 2024

## Incident Summary

**Duration:** 2 hours 15 minutes (14:30 - 16:45 UTC)
**Severity:** SEV-2
**Impact:** All CI pipelines blocked for main repository
**Detection:** Kenchi alert + engineer report

## Root Cause

The npm public registry implemented stricter rate limiting that affected our CI runners. With 50+ concurrent jobs, we exceeded the new limits causing `ETIMEDOUT` errors during `npm install`.

### Contributing Factors

1. **No dependency caching**: Each job downloaded all dependencies fresh
2. **High concurrency**: Matrix builds created 50+ parallel jobs
3. **No rate limit handling**: No retry logic for npm failures
4. **Lack of monitoring**: No alerts for npm registry latency

## Resolution

### Immediate Actions

1. Reduced job concurrency from 50 to 10
2. Enabled npm cache in CI configuration
3. Added retry logic for npm install step

### Long-term Fixes

1. Implemented Artifactory proxy for npm registry
2. Added dependency caching to all CI workflows
3. Created alerts for npm install failures
4. Documented rate limit handling procedures

## Lessons Learned

### What Went Well

- Kenchi detection provided early warning
- On-call response was quick
- Team collaboration was effective

### What Went Wrong

- No dependency caching despite best practices
- Rate limit scenario not considered in CI design
- Recovery took longer than necessary
