## Overview

Confidence scoring is a **deterministic process** that evaluates the quality and reliability of LLM-generated analysis to determine whether the system should act on its recommendations. This is a critical safety mechanism that prevents the system from taking actions based on uncertain, incomplete, or potentially incorrect AI analysis.

### Purpose

- Quantify the reliability of LLM analysis (0.0 to 1.0 scale)
- Gate actions based on confidence thresholds
- Require human approval for low-confidence recommendations
- Provide transparency to users about AI certainty

### Key Principle

**The confidence score is NOT generated by the LLM itself** (LLMs are notoriously poor at self-assessment). Instead, it is **computed deterministically** by analyzing various signals in the LLM's output and comparing it against the evidence.

### Confidence Score Range

- **0.0 - 0.3**: Very Low - Block automatic actions, flag for human review
- **0.3 - 0.5**: Low - Require approval for all actions
- **0.5 - 0.7**: Medium - Require approval for medium+ risk actions
- **0.7 - 0.85**: High - Auto-approve safe actions, require approval for risky ones
- **0.85 - 1.0**: Very High - Auto-approve low/medium risk actions

## Base Score Determination

### Step 1: Extract LLM's Stated Confidence

The LLM is asked to provide a confidence level in its response. This serves as the **starting point** but is adjusted by subsequent factors.

#### Mapping Table

| LLM Stated Confidence | Base Score | Notes                                    |
| --------------------- | ---------- | ---------------------------------------- |
| `very_high`           | 0.85       | LLM explicitly states high certainty     |
| `high`                | 0.75       | LLM is confident but not absolute        |
| `medium`              | 0.60       | LLM has moderate confidence              |
| `low`                 | 0.40       | LLM acknowledges uncertainty             |
| `very_low`            | 0.20       | LLM is very uncertain                    |
| Not provided          | 0.50       | Default to medium if LLM doesn't specify |

#### Code Example

```typescript
function getBaseScore(llmConfidence?: string): number {
  const confidenceMap: Record<string, number> = {
    very_high: 0.85,
    high: 0.75,
    medium: 0.6,
    low: 0.4,
    very_low: 0.2,
  };

  return confidenceMap[llmConfidence || ""] || 0.5; // Default to medium
}
```

## Adjustment Factors

After establishing the base score, apply a series of adjustments based on analysis of the LLM output and evidence.

### Factor 1: Uncertainty Detection

**Purpose**: Detect hedging language that indicates the LLM is uncertain, even if it stated a higher confidence level.

#### Uncertainty Markers

**Strong Uncertainty** (subtract 0.15-0.20):

- "I'm not sure"
- "It's unclear"
- "Cannot determine"
- "Insufficient information"
- "Unable to identify"
- "Unknown"

**Moderate Uncertainty** (subtract 0.08-0.12):

- "Possibly"
- "Might be"
- "Could be"
- "May be related to"
- "Potentially"
- "Perhaps"
- "Likely" (when used frequently)

**Mild Hedging** (subtract 0.03-0.05):

- "Appears to be"
- "Seems like"
- "Suggests that"
- "Indicates possible"
- "Probably"

#### Implementation

```typescript
interface UncertaintyPattern {
  pattern: RegExp;
  penalty: number;
  category: "strong" | "moderate" | "mild";
}

const uncertaintyPatterns: UncertaintyPattern[] = [
  // Strong uncertainty
  {
    pattern:
      /\b(not sure|unclear|cannot determine|insufficient information|unable to identify|unknown)\b/gi,
    penalty: -0.15,
    category: "strong",
  },

  // Moderate uncertainty
  {
    pattern: /\b(possibly|might be|could be|may be|potentially|perhaps)\b/gi,
    penalty: -0.1,
    category: "moderate",
  },

  // Mild hedging
  {
    pattern: /\b(appears to|seems like|suggests that|probably)\b/gi,
    penalty: -0.05,
    category: "mild",
  },
];

function detectUncertainty(text: string): number {
  let totalPenalty = 0;
  const normalizedText = text.toLowerCase();

  for (const { pattern, penalty } of uncertaintyPatterns) {
    const matches = normalizedText.match(pattern);
    if (matches) {
      // Apply penalty, but cap at pattern's max penalty even if multiple occurrences
      totalPenalty += penalty;
    }
  }

  // Cap total uncertainty penalty at -0.30
  return Math.max(totalPenalty, -0.3);
}
```

### Factor 2: Evidence Alignment

**Purpose**: Verify that the LLM's identified cause is supported by the evidence.

#### Alignment Checks

**Strong Alignment** (add 0.10-0.15):

- LLM's cause directly quotes from error logs
- Identified commit matches timeframe and symptoms
- Similar past incident found with same resolution
- Metrics clearly show the described problem

**Partial Alignment** (add 0.05):

- Some evidence supports the cause
- Indirect correlation between evidence and cause

**No Alignment** (subtract 0.15-0.20):

- LLM's cause not mentioned in evidence
- Contradicts available evidence
- Makes claims not supported by logs/metrics

#### Implementation

```typescript
interface AlignmentCheck {
  check: (analysis: LLMAnalysisResult, evidence: Evidence) => boolean;
  score: number;
  description: string;
}

const alignmentChecks: AlignmentCheck[] = [
  {
    check: (analysis, evidence) => {
      // Check if identified cause contains text from error logs
      const cause = analysis.identifiedCause?.toLowerCase() || "";
      return (
        evidence.logs?.some((log) => cause.includes(log.message.toLowerCase().substring(0, 50))) ||
        false
      );
    },
    score: 0.15,
    description: "Cause directly references error logs",
  },
  {
    check: (analysis, evidence) => {
      // Check if analysis references recent commits
      const reasoning = analysis.reasoning?.toLowerCase() || "";
      return (
        evidence.gitHistory?.some((commit) => reasoning.includes(commit.sha.substring(0, 7))) ||
        false
      );
    },
    score: 0.1,
    description: "Analysis references specific commits",
  },
  {
    check: (analysis, evidence) => {
      // Check if similar past incident was found
      return (
        evidence.relatedDocs?.some(
          (doc) => doc.type === "past_incident" && doc.similarity > 0.85
        ) || false
      );
    },
    score: 0.15,
    description: "High-similarity past incident found",
  },
  {
    check: (analysis, evidence) => {
      // Check if analysis mentions metrics that are actually anomalous
      const reasoning = analysis.reasoning?.toLowerCase() || "";
      const hasMetrics =
        reasoning.includes("cpu") ||
        reasoning.includes("memory") ||
        reasoning.includes("error rate");
      return hasMetrics && evidence.metrics?.summary !== undefined;
    },
    score: 0.05,
    description: "Analysis references relevant metrics",
  },
];

function calculateEvidenceAlignment(analysis: LLMAnalysisResult, evidence: Evidence): number {
  let alignmentScore = 0;

  for (const check of alignmentChecks) {
    if (check.check(analysis, evidence)) {
      alignmentScore += check.score;
    }
  }

  // If NO alignment checks passed, apply penalty
  if (alignmentScore === 0 && analysis.identifiedCause) {
    alignmentScore = -0.15;
  }

  // Cap at +0.20
  return Math.min(alignmentScore, 0.2);
}
```

### Factor 3: Completeness Assessment

**Purpose**: Evaluate whether the analysis is thorough and detailed.

#### Completeness Criteria

**Complete Analysis** (add 0.05-0.10):

- ✓ Root cause identified and explained
- ✓ Reasoning provided with evidence references
- ✓ Multiple recommended actions
- ✓ Impact assessment included
- ✓ No empty or "N/A" fields in critical sections

**Incomplete Analysis** (subtract 0.10-0.15):

- ✗ No root cause identified
- ✗ Minimal reasoning
- ✗ No recommended actions or only generic ones
- ✗ Missing expected fields

#### Implementation

```typescript
function assessCompleteness(analysis: LLMAnalysisResult): number {
  let score = 0;

  // Check if root cause identified (not just "unknown" or empty)
  if (
    analysis.identifiedCause &&
    analysis.identifiedCause.length > 20 &&
    !analysis.identifiedCause.toLowerCase().includes("unknown")
  ) {
    score += 0.03;
  }

  // Check if reasoning is substantial
  if (analysis.reasoning && analysis.reasoning.length > 100) {
    score += 0.03;
  }

  // Check if multiple actions recommended
  if (analysis.recommendedActions && analysis.recommendedActions.length >= 2) {
    score += 0.02;
  }

  // Check if impact assessment provided
  if (analysis.impactAssessment) {
    score += 0.02;
  }

  // Check if uncertainties are explicitly listed (transparency bonus)
  if (analysis.uncertainties && analysis.uncertainties.length > 0) {
    score += 0.03; // Bonus for transparency about limitations
  }

  // Penalty for minimal analysis
  if (!analysis.identifiedCause && !analysis.reasoning) {
    score -= 0.15;
  }

  return score;
}
```

### Factor 4: Knowledge Base Validation

**Purpose**: Boost confidence if the analysis aligns with known patterns from past incidents.

#### Validation Logic

**High Similarity to Past Incident** (add 0.10):

- Similar incident found with similarity > 0.85
- Past incident has documented resolution
- LLM references the past incident in reasoning

**Medium Similarity** (add 0.05):

- Similar incident found with similarity 0.70-0.85
- Pattern matches known issues

**No Similar Incidents** (neutral):

- No penalty, but no boost
- Novel issues are valid

#### Implementation

```typescript
function validateAgainstKnowledgeBase(analysis: LLMAnalysisResult, evidence: Evidence): number {
  const relatedIncidents =
    evidence.relatedDocs?.filter((doc) => doc.type === "past_incident") || [];

  if (relatedIncidents.length === 0) {
    return 0; // No penalty for novel issues
  }

  // Find highest similarity incident
  const bestMatch = relatedIncidents.reduce(
    (max, doc) => (doc.similarity > max.similarity ? doc : max),
    { similarity: 0 }
  );

  // Check if LLM references this incident
  const reasoning = analysis.reasoning?.toLowerCase() || "";
  const referencesIncident =
    reasoning.includes(bestMatch.id?.toLowerCase() || "") ||
    analysis.relatedIncidents?.includes(bestMatch.id || "") ||
    false;

  if (bestMatch.similarity > 0.85 && referencesIncident) {
    return 0.1; // Strong validation
  } else if (bestMatch.similarity > 0.7) {
    return 0.05; // Moderate validation
  }

  return 0;
}
```

### Factor 5: Consistency Check

**Purpose**: Ensure recommendations are consistent with the identified cause.

#### Consistency Checks

**Consistent** (add 0.05):

- Recommended actions logically address the identified cause
- Priority levels match severity
- No contradictory recommendations

**Inconsistent** (subtract 0.10):

- Actions don't address the stated cause
- Contradictory recommendations
- Severity mismatch

#### Implementation

```typescript
function checkConsistency(analysis: LLMAnalysisResult): number {
  if (!analysis.identifiedCause || !analysis.recommendedActions) {
    return 0;
  }

  const cause = analysis.identifiedCause.toLowerCase();
  const actions = analysis.recommendedActions;

  // Check if actions are relevant to cause
  let relevantActions = 0;
  for (const action of actions) {
    const actionDesc = action.description.toLowerCase();
    const actionType = action.actionType.toLowerCase();

    // Simple keyword matching (can be enhanced)
    if (cause.includes("secret") && actionType.includes("environment")) {
      relevantActions++;
    } else if (cause.includes("deploy") && actionType.includes("rollback")) {
      relevantActions++;
    } else if (cause.includes("config") && actionType.includes("configuration")) {
      relevantActions++;
    }
    // Add more heuristics as needed
  }

  const relevanceRatio = relevantActions / actions.length;

  if (relevanceRatio >= 0.5) {
    return 0.05; // At least half the actions are relevant
  } else if (relevanceRatio === 0) {
    return -0.1; // No actions seem relevant to cause
  }

  return 0;
}
```

## Scoring Algorithm

### Complete Calculation

```typescript
interface ConfidenceScoreResult {
  finalScore: number;
  breakdown: {
    baseScore: number;
    uncertaintyAdjustment: number;
    evidenceAlignment: number;
    completeness: number;
    knowledgeBaseValidation: number;
    consistency: number;
  };
  reasoning: string[];
}

function calculateConfidenceScore(
  analysis: LLMAnalysisResult,
  evidence: Evidence
): ConfidenceScoreResult {
  // 1. Base score from LLM's stated confidence
  const baseScore = getBaseScore(analysis.confidence);

  // 2. Detect uncertainty in text
  const uncertaintyAdjustment = detectUncertainty(
    `${analysis.summary} ${analysis.reasoning} ${analysis.identifiedCause}`
  );

  // 3. Check evidence alignment
  const evidenceAlignment = calculateEvidenceAlignment(analysis, evidence);

  // 4. Assess completeness
  const completeness = assessCompleteness(analysis);

  // 5. Validate against knowledge base
  const knowledgeBaseValidation = validateAgainstKnowledgeBase(analysis, evidence);

  // 6. Check consistency
  const consistency = checkConsistency(analysis);

  // 7. Compute final score
  let finalScore =
    baseScore +
    uncertaintyAdjustment +
    evidenceAlignment +
    completeness +
    knowledgeBaseValidation +
    consistency;

  // Clamp to [0, 1]
  finalScore = Math.max(0, Math.min(1, finalScore));

  // Generate reasoning
  const reasoning: string[] = [];
  reasoning.push(
    `Base score: ${baseScore.toFixed(2)} (from LLM confidence: ${analysis.confidence || "medium"})`
  );

  if (uncertaintyAdjustment !== 0) {
    reasoning.push(
      `Uncertainty adjustment: ${uncertaintyAdjustment > 0 ? "+" : ""}${uncertaintyAdjustment.toFixed(2)}`
    );
  }
  if (evidenceAlignment !== 0) {
    reasoning.push(
      `Evidence alignment: ${evidenceAlignment > 0 ? "+" : ""}${evidenceAlignment.toFixed(2)}`
    );
  }
  if (completeness !== 0) {
    reasoning.push(`Completeness: ${completeness > 0 ? "+" : ""}${completeness.toFixed(2)}`);
  }
  if (knowledgeBaseValidation !== 0) {
    reasoning.push(`Knowledge base validation: +${knowledgeBaseValidation.toFixed(2)}`);
  }
  if (consistency !== 0) {
    reasoning.push(`Consistency: ${consistency > 0 ? "+" : ""}${consistency.toFixed(2)}`);
  }

  reasoning.push(`Final confidence score: ${finalScore.toFixed(2)}`);

  return {
    finalScore,
    breakdown: {
      baseScore,
      uncertaintyAdjustment,
      evidenceAlignment,
      completeness,
      knowledgeBaseValidation,
      consistency,
    },
    reasoning,
  };
}
```

## Implementation Guide

### Integration Points

#### 1. After LLM Analysis

```typescript
// After receiving LLM analysis
const llmAnalysis: LLMAnalysisResult = await openaiClient.generateAnalysis(event, evidence);

// Compute confidence score
const confidenceResult = calculateConfidenceScore(llmAnalysis, evidence);

// Add score to analysis result
llmAnalysis.confidenceScore = confidenceResult.finalScore;

// Log breakdown for debugging
logger.info("Confidence score calculated", {
  eventId: event.id,
  score: confidenceResult.finalScore,
  breakdown: confidenceResult.breakdown,
  reasoning: confidenceResult.reasoning,
});
```

#### 2. Before Creating Action Proposals

```typescript
// Gate action creation based on confidence
if (confidenceResult.finalScore < 0.3) {
  logger.warn("Very low confidence, flagging for human review", {
    eventId: event.id,
    score: confidenceResult.finalScore,
  });

  // Create notification but no automated actions
  await notifyHumanReview(event, llmAnalysis, confidenceResult);
  return;
}

// Create action proposals with confidence score
const proposals = llmAnalysis.recommendedActions.map((action) =>
  createActionProposal(action, llmAnalysis, confidenceResult.finalScore)
);
```

Store confidence scores and breakdowns for:

- **Analytics**: Track confidence distribution over time

- **Debugging**: Understand why scores were high/low

## Action Gating Rules

### Decision Matrix

| Confidence Score | Safety Level | Decision                       | Rationale                                                |
| ---------------- | ------------ | ------------------------------ | -------------------------------------------------------- |
| 0.85 - 1.0       | Safe         | **Auto-approve**               | Very high confidence + safe action = automatic execution |
| 0.85 - 1.0       | Low Risk     | **Auto-approve**               | Very high confidence allows low-risk automation          |
| 0.85 - 1.0       | Medium Risk  | **Require approval**           | Even with high confidence, medium risk needs human check |
| 0.85 - 1.0       | High Risk    | **Require approval**           | Always require approval for high-risk actions            |
| 0.70 - 0.84      | Safe         | **Auto-approve**               | High confidence + safe = automatic                       |
| 0.70 - 0.84      | Low Risk     | **Require approval**           | Need human confirmation for lower confidence             |
| 0.70 - 0.84      | Medium+ Risk | **Require approval**           | Always require approval                                  |
| 0.50 - 0.69      | Any          | **Require approval**           | Medium confidence always needs approval                  |
| 0.30 - 0.49      | Any          | **Require approval + Warning** | Low confidence, warn user                                |
| 0.0 - 0.29       | Any          | **Block + Manual review**      | Very low confidence, do not execute                      |

### Implementation

```typescript
function determineActionGating(
  action: ActionProposal,
  confidenceScore: number
): { requiresApproval: boolean; autoExecutable: boolean; message: string } {
  const { safetyLevel } = action;

  // Very low confidence: block everything
  if (confidenceScore < 0.3) {
    return {
      requiresApproval: true,
      autoExecutable: false,
      message: "Very low confidence. Manual review required before any action.",
    };
  }

  // Low confidence: require approval with warning
  if (confidenceScore < 0.5) {
    return {
      requiresApproval: true,
      autoExecutable: true,
      message: "Low confidence. Careful review recommended.",
    };
  }

  // Medium confidence: require approval
  if (confidenceScore < 0.7) {
    return {
      requiresApproval: true,
      autoExecutable: true,
      message: "Medium confidence. Approval required.",
    };
  }

  // High confidence (0.7-0.84)
  if (confidenceScore < 0.85) {
    if (safetyLevel === "safe") {
      return {
        requiresApproval: false,
        autoExecutable: true,
        message: "High confidence with safe action. Auto-approved.",
      };
    } else {
      return {
        requiresApproval: true,
        autoExecutable: true,
        message: "High confidence but risky action. Approval required.",
      };
    }
  }

  // Very high confidence (0.85+)
  if (safetyLevel === "safe" || safetyLevel === "low_risk") {
    return {
      requiresApproval: false,
      autoExecutable: true,
      message: "Very high confidence with low-risk action. Auto-approved.",
    };
  } else if (safetyLevel === "high_risk" || safetyLevel === "dangerous") {
    return {
      requiresApproval: true,
      autoExecutable: true,
      message: "High-risk action always requires approval regardless of confidence.",
    };
  } else {
    return {
      requiresApproval: true,
      autoExecutable: true,
      message: "Medium-risk action requires approval.",
    };
  }
}
```

```typescript
    baseScore: 0.60,          // LLM said "medium"
    uncertaintyAdjustment: -0.05, // "may have" detected
    evidenceAlignment: 0.05,  // Some evidence (timeout log)
    completeness: 0.05,       // Decent analysis
    knowledgeBaseValidation: 0, // No past incidents

```

**Action Gating**: With 0.65 confidence (medium), **require approval** for all actions, especially the rollback (high-risk action).

## Tuning & Calibration

### Feedback Loop

To improve confidence scoring over time:

1. **Collect Outcomes**: After each incident, record whether the LLM analysis was correct
2. **Analyze Mismatches**: Identify cases where confidence was high but analysis was wrong (or vice versa)
3. **Adjust Weights**: Fine-tune penalty/bonus values based on patterns
4. **A/B Testing**: Test different scoring parameters on historical data

### Metrics to Track

```typescript
interface ConfidenceMetrics {
  // Accuracy by confidence bucket
  accuracyByConfidence: {
    very_low: { correct: number; total: number; accuracy: number };
    low: { correct: number; total: number; accuracy: number };
    medium: { correct: number; total: number; accuracy: number };
    high: { correct: number; total: number; accuracy: number };
    very_high: { correct: number; total: number; accuracy: number };
  };

  // Calibration: are we over/under confident?
  calibration: {
    avgConfidenceWhenCorrect: number;
    avgConfidenceWhenIncorrect: number;
  };

  // Action outcomes
  autoApprovedActions: {
    successful: number;
    failed: number;
    successRate: number;
  };

  // False positive/negative rates
  falsePositives: number; // High confidence but wrong
  falseNegatives: number; // Low confidence but actually correct
}
```

### Calibration Goals

**Well-calibrated system**:

- 95% of incidents with 0.90+ confidence should have correct analysis
- 70% of incidents with 0.70 confidence should be correct
- 50% of incidents with 0.50 confidence should be correct

If actual accuracy is lower than confidence suggests, the scoring is **overconfident** and needs more aggressive penalties.

If actual accuracy is higher, the scoring is **underconfident** and can be relaxed.

## Future Enhancements

### 1. Machine Learning Model

Replace heuristic scoring with a trained model that learns from outcomes:

- Input: LLM analysis + evidence features
- Output: Confidence score
- Training data: Historical incidents with human-labeled correctness

### 2. Ensemble Scoring

Combine multiple scoring approaches:

- Heuristic score (current approach)
- ML model score
- Secondary LLM judge score
- Weighted average

### 3. Context-Aware Scoring

Adjust confidence based on:

- Event type (some types are easier to diagnose)
- Time of day (more evidence available during business hours)
- Service criticality (be more conservative for critical services)

### 4. Human Feedback Integration

Allow users to rate analysis quality:

- "This analysis was helpful/accurate"
- "This analysis was wrong/misleading"
- Use feedback to retrain models or adjust heuristics
